# AGENTS.md — Otogi: Myth of Demons static recompilation

You are a coding agent working on a static recompilation of the original Xbox
game *Otogi: Myth of Demons* (FromSoftware / Sega, 2002) into a native Windows
x86-64 executable, using the `xboxrecomp` toolkit.

Read this file first, every session. Then `docs/INDEX.md`.

## 1. What this project is (and is not)

- We do **not** emulate and we do **not** interpret. The game's own x86 is
  translated to C by the toolkit's recompiler and compiled natively.
- We do **not** write game logic. No hand-written menus, no fake screens, no
  substitute renderer. If the game shows something, the game's own code did it.
- Generated C is **never** hand-edited. It is an output, like a `.o` file.

## 2. The hard rules

1. **Never edit `src/game/recomp/gen/**`.** It is regenerated by `regen.sh` and
   gitignored. Edits there are destroyed on the next run.
2. **Fixes go in exactly three places**, in this order of preference:
   - `config/seed_functions.json` — title-specific function seeds/overrides.
   - `src/game/recomp_manual.c` — hand-written replacements for individual
     lifted functions, registered in the manual lookup table.
   - the `xboxrecomp` toolkit itself — if the bug is general (lifter, kernel
     shim, D3D translation). Raise it as a toolkit issue/PR; do not fork it
     silently into this repo.
3. **Never distribute game data or generated source.** `game/` and
   `src/game/recomp/gen/` stay gitignored. The user supplies their own disc.
4. **Never commit a disc image, XBE, or extracted assets.**

## 3. Environment (verify before first build)

- Windows 10/11 preferred — the D3D11 backend is the complete path; Linux/macOS
  only have the less-complete OpenGL 3.3 backend.
- Python 3.10+ with `capstone`.
- CMake 3.20+, Visual Studio 2022 (C/C++ desktop workload).
- The toolkit cloned alongside this repo (default `../xboxrecomp`).
- `extract-xiso` or the toolkit's `tools.xiso` to unpack the disc.
- xemu + Ghidra/IDA (optional but strongly recommended — see §6).

## 4. The pipeline, in one breath

`extract → xbe_parser → disasm → func_id → abi_analysis → [ghidra_naming] →
recomp → cmake build → run → read stderr → fix → repeat`

`regen.sh` drives steps 2–6. Full command detail: `docs/PIPELINE.md`.
The toolkit's own long-form guide is authoritative when something diverges.

## 5. Non-negotiable pipeline gates

These are the ways the pipeline fails *silently*. Do not skip them.

- **`abi_analysis` (Step 4.5) is mandatory.** If `abi_functions.json` is
  missing, `tools.recomp` warns once and falls back to `cdecl` / 0 params /
  `int_or_void` for *every* function. The recompile still succeeds and the code
  still builds — with wrong signatures everywhere. Silent, expensive.
- **`--split 250`, never `--split 1000`.** Large chunks produce ~250 MB
  translation units; that has OOM-killed a 15 GB machine. If the build dies on
  a signal rather than an error, check `dmesg` for the OOM killer before
  blaming the generated code.
- **`--gen-dir` must point into this repo** (`src/game/recomp/gen`). Without it
  the C lands inside the toolkit clone where nothing compiles it.
- **Ghidra naming runs *before* Step 5, and is lost if you re-run Step 3.**
  `tools.disasm` rewrites `functions.json` from scratch. Re-apply with
  `merge_names.py --apply`.
- **The first run will crash.** That is the expected starting state, not a
  regression.

## 6. Debugging loop (the actual work)

1. Run. Read `stderr.txt`.
2. Classify: ICALL miss / bad memory access / unimplemented kernel fn /
   corrupted vtable.
3. Fix in the allowed locations (§2).
4. Rebuild. Repeat. Log the finding in `docs/BOOT_LOG.md`.

Use the **ICALL trace** — the single most useful signal:
[ICALL] unknown target 0x001A3F50 from RVA 0x000165F0


Use **xemu** as the oracle: run the same scene in xemu under GDB to learn what
a memory address *means* when the recompiled build disagrees.

Remember the 80/20 rule: ~80% of lifted functions "just work". All your time is
in the other 20% — stubs, indirect calls, and hardware-facing code.

## 7. Useful runtime environment variables

| Variable | Purpose |
|---|---|
| `RECOMP_ABI_CHECK` | Assert lifted signatures against recovered ABI |
| `RECOMP_PB_EXEC` | Software NV2A push-buffer executor on/off |
| `RECOMP_USB` | USB OHCI host + emulated pads on/off |
| `RECOMP_PAD_LIVE` | Drive the title headless from a live pad |
| `RECOMP_FRAME_TRACE` | Frame tracing (takes a flag file, not `1`) |

Confirm current names against the toolkit before relying on them.

## 8. Commit conventions

- One finding per commit where possible; message states the symptom and the
  fix, e.g. `boot: stub XAPI quick-reboot; reach CRT startup`.
- Never commit generated code, disc data, or build output.
- Keep `docs/BOOT_LOG.md` append-only. Corrections go in new entries.

## 9. When you are stuck

- Re-read `docs/technical/indirect-calls.md` and `lessons-learned.md` in the
  toolkit.
- Check whether a general fix belongs upstream in `xboxrecomp`.
- Record the blocker in `docs/BOOT_LOG.md` with the exact stderr and RVA, then
  stop and report — do not "fix" it by hand-writing game behaviour.
